Distributed training · 4 GPUs · ring collectives

ZeRO Collectives Lab

Four GPUs train the same 2-layer model with 8 weights. Each GPU trains on different data, so the GPUs have to combine their gradients. Pick a method, then press Next to step through one training step and watch every number move, one send at a time.

    What each method costs, per GPU

    Counts are numbers, one box each. With 4 GPUs and 2 layers the savings look modest. The real run in this repo uses 32 GPUs and 4.2 million weights: a DDP GPU keeps 67.7 MB of model state, a ZeRO-3 GPU keeps 2.1 MB between steps.

    Playground: one collective on its own

    GPU 0 starts with 1, 2, 3, 4. GPU 1 has ten times that, GPU 2 a hundred times, GPU 3 a thousand times. So in any total, each digit tells you which GPU it came from: in 4321, the 4 came from GPU 3 and the 1 from GPU 0.

    A glowing button means the training step above is running that collective right now.

    The order of operations follows zero.py in this repo: DDP and ZeRO-1 combine gradients after backward, ZeRO-2 and ZeRO-3 reduce-scatter each layer as soon as its backward ends, and ZeRO-3 drops each layer's borrowed weights after forward and gathers them again for backward. Ring order is GPU 0 → 1 → 2 → 3 → 0. Keys: ← and → step through phases.
